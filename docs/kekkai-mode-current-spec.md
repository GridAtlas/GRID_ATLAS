# GRID ATLAS 結界モード 現行仕様・実装状況

更新日：2026-08-14
対象：Web版 0.1582
状態：現在の実装を基準にした引き継ぎ用仕様書

この文書は、GRID ATLAS Web版に現在入っている結界モードの仕様と実装状況をまとめたものです。提案中のアイデアや将来仕様は「未実装・保留」に分けています。

## 1. 用語

- モード名：結界モード
- 操作対象：結界石
- 3個以上の結界石をつないだ図形：結界
- プレイヤー全体の称号：結界師ランク
- 旧実装・内部関数には `traverse` / `traverse-log` という互換用の名称が残っていますが、ユーザー向けの名称は「結界」で統一します。

## 2. ゲームの基本フロー

1. 設定メニューで「結界モード」をONにする。
2. グリッド上の結界操作ボタンを長押しする。
3. ポップアップメニューから「置く」または「拾う」を選ぶ。
4. GPS位置から決まるタイルに結界石を1個追加、または1個回収する。
5. 3個以上の結界石を選択し、選択順に結んで結界を作成する。
6. 結界は日次評価パスで結界力・発動日数・結界師の発動量に反映される。

結界モード中も、地点・線・観察記録の選択、地点登録、接続、分析、巡回、削除、共有、長押しクイック操作など通常モードの操作をそのまま利用できます。通常のアクションバーのラベルや挙動は変更しません。結界石の操作と結界作成だけは、グリッド上の結界ボタンと、そのポップアップに集約します。結界石を選択して結界を作成する場合は、グリッド上で石を選択した後、結界ボタンのポップアップから「結界を張る」を実行します。

結界石があるタイルは、表示範囲を広げて縮小表示した場合も、地点の◯より一回り大きい画面サイズを下限とします。拡大時は通常のタイル倍率に従って大きくなります。表示上の拡大後のタイル形状を、石のクリック判定にも使います。

結界モードOFF時は、通常のGRID ATLASの地点・リンク操作を使います。結界モードの表示を通常の格子スケール表示へ追加する仕様はありません。

## 3. 結界石

### 3.1 保存単位

結界石はWeb Mercatorのズーム18タイル単位で管理します。

```text
stoneId = stone-{z}/{x}/{y}
```

石データにはタイルID、表示用の整数個数、内部計算用の小数個数、最初の配置時刻、最後の配置・回収・風化時刻を持ちます。緯度・経度と風化用の頂点タイマーは保存しません。

### 3.2 ストック

| 項目 | 現在値 |
|---|---:|
| 1日配給 | 3個 |
| 配給時刻 | 利用者のローカル時刻 12:00・20:00・翌04:00 に1個ずつ |
| ストック上限 | 20個 |
| GPS精度上限 | 100m |
| タイル判定ズーム | 18 |

アプリ起動時または結界モードON時に、前回の確認時刻以降に通過した配給時刻の数だけストックを補充します。1日分の3個を一度に増やさず、利用者のローカル時刻12:00、20:00、翌04:00に1個ずつ増えます。アプリを閉じていた場合は通過済みの配給分をまとめて反映し、ストックは上限20個を超えません。`stock.lastGrantAt` は最後に反映した配給時刻を保持します。

### 3.3 タイルごとの石数上限

| タイルの状態 | 上限 |
|---|---:|
| いずれかの結界の頂点 | 100個 |
| どの結界の頂点でもない | 20個 |

上限に達した場合はエラー通知ではなく、「置く」ボタンを無効化して静かに停止します。頂点になったタイルの上限は20から100へ上がります。頂点から外れた場合に、既存の石を自動削除したり20個まで減らしたりはしません。

## 4. 生イベントと保存

保存先はブラウザの `localStorage` です。

```text
キー：grid-atlas-barrier-log-v1
旧キー：grid-atlas-traverse-log-v1
ログ種別：barrier-log
スキーマ：3
```

ログには、現在状態に加えて `events` 配列を保持します。スコアやランクの計算結果だけを履歴の正本にはせず、入力イベントを残します。

主なイベント種別：

- `stone-placed`：石を置いた。タイル、日時、石ID、当時の結界ID、増加量、置いた後の `countExact` を記録。
- `stone-picked`：石を拾った。タイル、日時、石ID、当時の結界ID、減少量、拾った後の `countExact` を記録。
- `stone-weathered`：風化で整数表示値が減少した時だけ記録。タイル、日時、石ID、当時の結界ID、表示上の減少量、風化後の `countExact` を記録。
- `barrier-created`：結界の作成。結界ID、名前、頂点順、作成日時、作成時の守護点、作成時のランク進捗を記録。
- `barrier-snapshot`：旧形式ログからの移行用スナップショット。
- `guardian-placed` / `guardian-label-updated` / `guardian-removed`：守護点の操作。
- `daily-evaluation`：経過日数、評価後の `lastEvaluatedAt`、`dailyPower`、`lifetimeOutput` を記録。
- `evaluation-settings`：評価設定が前回記録時から変わった時だけ、評価時点の設定値を記録。

### イベントだけで再計算できる範囲

- 石の配置・回収：イベントを順に再生すれば、タイルごとの現在の石数を復元できます。
- 結界の作成：頂点順、名前、作成時の守護点、作成時のランク進捗を復元できます。現行Webには作成後の形変更イベントはありません。
- 守護点：設置、ラベル変更、削除を復元できます。守護点の設置イベントには生の緯度経度とラベルが入ります。
- 結界力・発動量・結界師ランク：今後記録される `stone-placed` / `stone-picked` / `barrier-created` と日次評価イベントを時系列で使えば、派生値を別設定で再計算できます。現在値の検算用として `daily-evaluation` に `dailyPower` と `lifetimeOutput` も残しますが、再採点の入力には使いません。
- 風化：`daily-evaluation` の評価時刻と経過日数、石の配置・回収時刻、結界作成時刻から再生できます。別の `weatherRate` で再計算する場合は、`stone-weathered` を入力イベントではなく現行実装が残した派生イベントとして無視します。過去ログにこれらの新イベントがない期間は、完全な再採点の対象にできません。

`barrier.js` の `replayBarrierEvents()` により、イベントから石・結界・守護点の状態を復元できます。再採点では `daily-evaluation` と `evaluation-settings` を評価区間の境界・設定履歴として使い、風化の中間値は保存せず計算で再現します。`stone-weathered` は現行状態の復元用には使えますが、再採点では二重適用を避けるため入力から除外します。

## 5. 結界の作成

- 3個以上の異なる結界石が必要です。
- 頂点数は `maxVertices = 6` 以下である必要があります。
- 7個以上の頂点を新規作成しようとすると、「結界の頂点は6つまでです」と拒否します。
- 存在しない石は選択できません。
- すでに別の結界の頂点になっている石は再利用できません。
- 選択順が結ぶ順序になります。
- 作成時に結界名を入力できます。
- 現在、結界そのものの削除機能と名称変更機能はありません。したがって、それらのイベントもありません。
- 結界を作成した回数は `kekkaishi.kekkaiCreatedCount` に累積します。

## 6. 結界力

結界力は次の4要素の積です。

```text
結界力 = 石の総数 × 形状係数 × 美しさ係数 × 規模係数
```

### 6.1 形状係数

| 形状 | 係数 |
|---|---:|
| 三角形 | 1.0 |
| 四角形 | 1.2 |
| 五角形 | 1.5 |
| 六角形 | 1.8 |
| 五芒星 | 3.0 |

自己交差する五頂点形状は五芒星として扱われます。7頂点以上は新規作成できないため、形状係数表の得点経路はここで閉じています。破損データなどの防御的なフォールバックとして、範囲外の既存データには1.8を返し、開発者向け警告を出します。

### 6.2 美しさ係数

守護点が設定されている場合は守護点、設定されていない場合は頂点の重心を基準に、頂点距離と角度の均整から算出します。係数は `0.5〜3.0` に収めます。

守護点は結界の形状・面積・石数を変更しません。美しさ係数の基準点だけを変更します。

### 6.3 規模係数

面積を `A [km²]`、`S = √A`、飽和距離を `SCALE_L0` として、現在は次の式です。

```text
規模係数 = S / (1 + S / SCALE_L0)
SCALE_L0 = 30km
```

面積が大きいほど単調増加しますが、規模係数は30へ漸近します。濃度は従来どおり次の表示です。

```text
濃度 = 結界力 / 面積
```

## 7. 風化

風化は結界の頂点タイルにある石だけへ適用します。どの結界にも属さない石は、放置しても風化しません。

```text
r = WEATHER_RATE = 0.001
d日経過後の石数 = countExact × (1 - r)^d
```

定着閾値は廃止しています。石数100個の頂点も風化します。1タイルあたりの上限100個／20個は変更ありません。

石数は内部的には `countExact`（小数）で保持し、表示・結界力・上限判定には `floor(countExact)` を使います。石を置くと `countExact += 1`、拾うと `countExact -= 1` します。風化後の `countExact` は頂点ごとに最低1へクランプします。

風化に頂点別タイマーは使いません。日次評価パスの経過日数 `d` と、現在その石がいずれかの結界の頂点かどうかだけで計算します。風化による整数表示値の減少があった場合のみ `stone-weathered` イベントを記録し、イベントには再評価用の `countExact` も保存します。

## 8. 統合日次評価パス

評価時刻はプレイヤー単位で1つだけです。

```text
kekkaishi.lastEvaluatedAt
```

結界ごとには評価時刻を持ちません。結界ごとに持つのは、発動日数と前回結界力です。

アプリ起動時、結界モードON時、結界師ステータスを開く時に評価を試みます。同一日時に再度呼び出しても、1日未満なら何も加算しません。

処理順序：

1. `d = floor((現在時刻 - lastEvaluatedAt) / 1日)` を求める。
2. `d < 1` なら終了する。
3. 各結界の頂点へ風化を適用する。
4. 風化後の結界力を `P_now` として再計算する。
5. 前回結界力 `P_prev` と `P_now` の小さい方を保守的な評価値にする。
6. その評価値が各ランクの力閾値以上なら、発動日数へ `d` 日を加える。
7. 全結界の保守的な評価値を合計して `dailyPower` とする。
8. `lifetimeOutput += dailyPower × d` とする。
9. `dailyHistory` に `dailyPower` を `d` 日分追加し、直近90日だけ残す。
10. 各結界の `lastPower` を `P_now` に更新する。
11. `kekkaishi.lastEvaluatedAt` を現在時刻ではなく、切り捨てた `d` 日分だけ進める。

```text
P_eval = min(P_prev, P_now)
dailyPower = Σ(P_eval)
```

結界が存在しない期間は `dailyPower = 0` として履歴に記録します。長期間アプリを開かなかった場合も、経過日数分を一括処理します。

新しく結界を作る際は、作成前に評価パスを一度通します。これにより、作成前の期間へ新しい結界の力が遡って加算されません。

## 9. 結界ランク

結界ランクは保存せず、結界ごとの `activeDays` から毎回導出します。風化や休止で発動日数が減ることはありません。これは結界ごとのランクであり、結界師ランクとは別です。

| ランク | 力の閾値 | 必要発動日数 |
|---|---:|---:|
| 標（しるべ） | 0 | 0日 |
| 注連（しめ） | 25 | 7日 |
| 垣（かき） | 100 | 30日 |
| 結界（けっかい） | 400 | 90日 |
| 霊域（れいいき） | 1,600 | 180日 |
| 聖域（せいいき） | 6,400 | 365日 |
| 神域（しんいき） | 102,400 | 730日 |

ランクRの発動日数は、`min(P_prev, P_now) >= POWER_THRESHOLD[R]` の日だけ加算されます。風化や休止で現在の結界力が下がっても、すでに得た発動日数とランクは下がりません。

結界詳細画面では、現在ランクに加えて次のランクまでの「力」と「発動日数」を2軸で表示します。

### 結界ごとの保存データ

```js
rankProgress: {
  activeDays: number[],
  lastPower: number | null
}
```

`rank` や `lastEvaluatedAt` は結界データに保存しません。

## 10. 結界師ステータス

結界師ステータスは、設定メニュー内の「結界師ステータス」から開きます。結界モードOFF時はボタンを無効化します。

表示項目：

- 結界師ランク（F〜S）
- 生涯発動量（単位：結界日）
- 最高平均発動力（全盛期）
- 全盛期を達成した年月
- 直近90日平均発動力
- 全盛期比
- 張った結界の累計数
- 次のランクまでの生涯発動量の進捗

直近90日平均には等級名を付けません。履歴が90日未満でも、未経過分を0で埋めて常に90で割ります。全盛期比は次の式です。

```text
全盛期比 = 直近90日平均 / 最高平均発動力 × 100
```

最高平均発動力は初日から記録します。`peakAverage = max(peakAverage, sum(dailyHistory) / 90)` で更新します。`peakAverage` が0の場合、全盛期比は `—` と表示します。

### 結界師ランクの現行実装

結界師ランクは生涯発動量だけを満たす最大ランクです。`peakAverage`、全盛期の年月、直近平均、全盛期比は表示専用で、段位判定には使いません。ランク自体は保存せず、値から導出します。

| ランク | 生涯発動量以上 |
|---|---:|
| F | 0 |
| E | 100 |
| D | 1,000 |
| C | 5,000 |
| B | 20,000 |
| A | 100,000 |
| S | 500,000 |

設定配列は `kekkaishiLifetimeThresholds = [0, 100, 1000, 5000, 20000, 100000, 500000]` です。`kekkaishiPeakThresholds` と `kekkaishiSustainDays` は存在しません。

### 結界師データ

```js
kekkaishi: {
  lifetimeOutput: number,
  dailyHistory: number[],
  peakAverage: number,
  peakAchievedAt: string,
  lastEvaluatedAt: string,
  lastDailyPower: number,
  kekkaiCreatedCount: number
}
```

生涯発動量、全盛期、結界作成数は減少しません。直近90日平均だけは休止や結界力低下によって下がります。

現在の日次発動力 `lastDailyPower` を表示します。次の段位について、生涯発動量の不足量を `lastDailyPower` で割って切り上げた日数目安を表示し、日次発動力が0なら「結界を張ると進みます」と表示します。

## 11. 守護点

各結界には任意で守護点を1つ設定できます。

- 地図上で守る場所を指定する。
- ラベルを付ける、変更する、削除する。
- 守護点は結界力の美しさ係数の基準点になる。
- 守護点の設置・削除・ラベル変更では結界の発動日数をリセットしない。

## 12. 共有画像

### 結界共有画像

選択中の結界を画像化します。結界名、図形、石数、結界力、面積、形状係数、美しさ係数、ランクなどを含みます。守護点ラベルは設定で表示・非表示を切り替えられます。

### 結界師ステータス共有画像

位置情報を含めない数値カードです。結界師ランク、生涯発動量、最高平均発動力、直近平均、作成した結界数を含み、座標、結界の図形、石の位置、守護点は含めません。

## 13. 設定値の場所

結界石・GPS・風化設定は `src/barrier.js` の `BARRIER_CONFIG`、規模係数・形状係数は `src/barrier-score.js` の `BARRIER_SCORE_CONFIG`、日次評価・ランク閾値は `src/barrier-evaluation.js` の `BARRIER_EVALUATION_CONFIG` にあります。

```js
// src/barrier.js
dataZoom: 18
maxVertices: 6
dailyGrant: 3
stockGrantHours: [4, 12, 20]
stockCap: 20
stoneCapVertex: 100
stoneCapLoose: 20
weatherRate: 0.001
accuracyThresholdMeters: 100

// src/barrier-score.js
scaleL0: 30

// src/barrier-evaluation.js
windowDays: 90
powerThresholds: [0, 25, 100, 400, 1600, 6400, 102400]
daysRequired: [0, 7, 30, 90, 180, 365, 730]
kekkaishiLifetimeThresholds: [0, 100, 1000, 5000, 20000, 100000, 500000]
```

設定記録イベントには、上記に加えて `weatherRate`, `scaleL0`, `stoneCapVertex`, `dailyGrant`, `maxVertices` を含めます。設定値が前回記録時と同じなら重複記録しません。`peakAverage` は初日からゼロ埋め90日平均で更新され、表示専用です。

上記は自己プレイで調整する前提の現行値です。

## 15. 未実装・保留

### 15.1 結界の形変更UI

現行Web版には、作成済み結界の頂点追加・削除・結ぶ順序変更を行う編集UIがありません。そのため、仕様として定義されている次の処理は、編集UIを追加する段階で接続します。

- 形を変更する前の確認ダイアログ
- 変更前の発動日数とランクの表示
- 形変更時の `activeDays` リセット
- 変更後の結界力を `lastPower` に初期化

石を積む・拾う、守護点を操作する場合は発動日数をリセットしない方針です。

### 15.2 推移グラフ

直近90日の `dailyHistory` は保存済みですが、ステータス画面の折れ線グラフはまだ実装していません。

### 15.3 再採点画面

再採点画面はまだありません。ただし、今後の完全なイベント履歴には日次評価イベントと設定変更イベントが入り、石・結界・守護点の入力イベントも残るため、派生値を別設定で再計算できる材料は揃います。`stone-weathered` は別風化率の再採点では除外し、配置・回収・評価時刻から再計算します。既存の過去イベントに新イベントがない期間は、別設定での正確な再採点はできません。

### 15.4 events 配列の容量

`events` に上限、圧縮、古いイベントの整理処理はありません。今回追加した `daily-evaluation` は、経過日数 `d >= 1` の評価1回につき1件です。毎日アプリを開く運用なら通常1日1件、数日分をまとめて評価した場合は複数日でも1件です。サンプルJSONのUTF-8サイズは、日次評価イベントが約180〜220 bytes、設定イベントが約300〜400 bytesです。設定イベントは初回と設定変更時だけです。

今回追加分だけなら通常は約0.2 KB/日、設定変更日のみ約0.5〜0.6 KBが目安です。石の配置・回収・風化イベントは別途増え、風化イベントは表示整数値が減った時だけです。localStorageの容量見積もり・残量監視・上限到達時の退避処理は、現時点では実装していません。

## 16. 引き継ぎ時の注意

- `DECISIONS.md` にない新しい仕様を確定扱いにしない。
- `events` の入力履歴を削除せず、派生値だけを再計算可能に保つ。
- `kekkaishi.lastEvaluatedAt` と結界ごとの `lastPower` を混同しない。
- 結界師ランク、結界ランクを別の到達済みランクフィールドとして保存しない。
- 結界師ステータス共有画像へ位置情報を追加しない。
- 通常モードの格子スケール表示へ結界用の表示を追加しない。
