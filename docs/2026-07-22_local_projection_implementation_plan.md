# GRID ATLAS ローカル投影対応 実装計画書

作成日: 2026-07-22  
対象: 緯度の高い地域、日付変更線付近、世界各地での距離感と配置の破綻を防ぎ、GRID ATLASらしい「自分と地点の距離感」を保つための表示座標基盤

## 1. 目的

GRID ATLASの本質は、地図を読むことではなく、自分と登録地点の距離・方向・接近感を格子上で読むことにある。

現在のWeb Mercator投影は、地球全体を一枚の平面に並べる用途には便利だが、次の問題がある。

- 高緯度ほど、同じ経度差の表示距離が実距離より大きくなる。
- 経度180度付近をまたぐ地点が、実際には近いのに画面の左右端へ分断される。
- 極に近づくほど、緯度経度を平面上の距離感として扱うこと自体が不自然になる。
- `fit`、追跡の自動スケール、線の描画、タップ判定が同じ歪みの影響を受ける。

これを、表示用のローカル投影に切り替えることで改善する。保存データの緯度経度や、地球上の直線距離の計算は変更しない。

## 2. 変更しない原則

### 2.1 地理データの正本

地点、現在地、観察軌道、起点スナップショットは、これまでどおり緯度経度を正本とする。

```js
geo: {
  lat: 35.681236,
  lng: 139.767125,
  accuracy: 18
}
```

`x` と `y` は保存してもよいが、表示時に再計算できるキャッシュ扱いとする。投影方式変更のたびに保存ファイルを変換する必要がない設計にする。

### 2.2 距離の正本

地点間距離、残距離、実軌道距離、道直比、巡回順は、緯度経度から計算する球面距離を使う。表示用の平面距離を分析値として流用しない。

### 2.3 GRID ATLASの画面思想

- 外部地図タイル、地名、道路、地形は表示しない。
- グリッドの1マスは、表示中心付近での実距離を示す。
- 起点、対象、現在地、通常地点、観察軌道の相対関係を崩さない。
- 投影方式の変更によって、既存の操作体系を変えない。

## 3. 推奨する投影方式

### 3.1 ローカル表示: 方位距離投影

表示の主役は、表示中心を基準にしたローカルな方位距離投影とする。中心から各地点までの半径を球面距離、角度を初期方位として平面に置く方式である。

数式上は、中心を `(lat0, lng0)`、地点を `(lat, lng)`、地球半径を `R` とする azimuthal equidistant projection を基本候補にする。

```text
dlng = shortestLongitudeDelta(lng - lng0)
c = angularDistance(lat0, lng0, lat, lng)
k = c / sin(c)
x = R * k * cos(lat) * sin(dlng)
y = R * k * (cos(lat0) * sin(lat)
             - sin(lat0) * cos(lat) * cos(dlng))
```

中心近くでは、東西南北の距離感が自然で、中心から地点までの距離も保たれる。日付変更線をまたいでも `shortestLongitudeDelta` によって近い方向へ配置できる。中心を極付近に置いても、Web Mercatorのような緯度による無限大の拡大は起きない。

### 3.2 世界俯瞰: 別モードとして扱う

1画面に地球規模の地点を同時表示する場合、単一のローカル投影だけで全地点の形状を自然に保つことはできない。地球は平面ではないためである。

したがって、次の2つを明確に分ける。

- `local`: 現在地・選択地点・追跡対象を中心に、距離感を優先する通常モード
- `world`: 全体表示や非常に広い範囲の俯瞰で、全地点が画面に収まることを優先するモード

初期実装では、ユーザーが使う主画面を常に `local` とし、全体表示ボタンだけが `world` を選ぶ構成を推奨する。世界俯瞰は正確な局所距離を読む画面ではなく、地点の存在範囲を確認する画面と位置付ける。

## 4. 投影コンテキスト

投影を関数単体で置き換えず、現在の表示に必要な値を一つのコンテキストにまとめる。

```js
state.projection = {
  mode: "local",
  centerGeo: null,
  centerWorld: { x: 0, y: 0 },
  radius: EARTH_RADIUS_METERS,
  version: 1
};
```

### 4.1 `centerGeo`の決め方

優先順位は次のとおりとする。

1. 追跡中: 現在地
2. 現在地への画面追従中: 現在地
3. 対象または起点を中心に表示する操作: その中心位置
4. 複数地点の全体表示: 選択地点の地理的中心
5. 初回起動で現在地が取れない場合: 既定中心（東京）

投影中心は、パン操作のたびには変更しない。パンは投影平面上のビューポート移動として扱う。投影中心を頻繁に変えると、ユーザーがグリッドをスライドした際に点や線が滑るように再配置され、現在すでに問題になっている違和感を再発させるためである。

### 4.2 投影中心を更新するタイミング

投影中心の更新を許可するのは、以下の明示的な場面に限定する。

- 起動時の現在地センタリング
- `◎` による現在地センタリング
- `🔲` の全体表示
- 追跡開始時の初期表示
- 地点リストの全体表示
- 投影モード切り替え

更新時は、変更前後で現在表示中の中心または主要対象が急に飛ばないよう、ビューポート中心とスケールを再計算する。

## 5. 座標変換APIの整理

既存の投影関数を以下の責務に分離する。

### 5.1 地理座標と投影座標

- `projectGeo(geo, projectionContext)`
- `unprojectWorld(world, projectionContext)`
- `projectLocalAeqd(geo, centerGeo)`
- `unprojectLocalAeqd(world, centerGeo)`
- `projectWorldMercator(geo)`
- `unprojectWorldMercator(world)`

アプリ内の描画処理は `projectGeo` / `unprojectWorld` だけを呼び、Web Mercator固有の関数を直接呼ばない。

### 5.2 画面座標

現在の `worldToScreen`、`screenToWorld` は投影方式に依存しないまま維持する。投影座標を返す処理を統一できれば、Canvasの描画、ズーム、パン、ピンチは既存の構造を活かせる。

### 5.3 経度差

以下を共通関数として追加する。

```js
function shortestLongitudeDelta(fromLng, toLng) {
  return ((((toLng - fromLng) + 540) % 360) + 360) % 360 - 180;
}
```

日付変更線をまたぐ線、中心計算、経度差、表示範囲の計算でこの関数を使用する。生の経度差を使う箇所は残さない。

## 6. グリッドの仕様

### 6.1 グリッド間隔

ローカル投影では、グリッドの実距離を投影中心付近のメートル単位で直接扱う。

- `chooseGridStep()` は緯度補正済みのWeb Mercator距離を使わない。
- 既存の候補値（1, 2, 5系列）はメートル値としてそのまま使う。
- `drawGridLines()` は投影平面の `x=0` / `y=0` から距離間隔で描画する。
- ステータス表示の「格子 50.00 km」は、そのまま画面上の主要格子間隔を示す。

### 6.2 表示中心から離れた地点

ローカル投影の有効範囲を超えるほど遠い地点を無理に同じ局所格子へ押し込まない。次の基準で `world` への切り替えまたは再センタリングを検討する。

- 中心からの最長距離
- 画面に収めるために必要な縮尺
- 投影中心からの角距離
- 地点群の緯度・経度の分布

初期値は「中心から120度未満」「距離20,000km未満」を安全上限の候補とするが、実装時に数値テストで決定する。これは仕様上の固定値ではなく、検証対象とする。

## 7. 既存機能への影響と対応

### 7.1 点・線・観察軌道

以下は全て同じ `projectGeo` 経由で投影する。

- 登録地点
- 現在地
- 仮ポイント
- 起点固定マーカー
- 対象点
- 通常の接続線
- 起点から対象への点線
- 観察モードの実軌道
- 読み込んだ観察記録

描画順は現在の仕様を維持する。投影方式を変えても、起点・対象、現在地、通常地点の前後関係は変えない。

### 7.2 追跡モード

追跡中は現在地を投影中心にする。現在地が移動するたびに、ローカル投影の基準を現在地へ移すと過去の軌道が動いて見えるため、次のどちらかを採用する。

推奨は、追跡開始時に固定した `observationProjectionOrigin` を使う方式である。

- 追跡開始時に投影中心を確定
- その後は現在地をビューポート中心へ移動
- 現在地、対象、起点、実軌道を同じ固定投影で描画
- 距離が広がって局所投影の範囲を超えた場合だけ、観察を中断せずに再基準化する仕組みを別途検討

再基準化が必要になった場合は、過去の軌道を緯度経度から新しい投影へ再投影する。保存データの軌道点を書き換えない。

### 7.3 自動スケール

追跡対象との距離に応じた段階スケールは、現在の球面距離計算をそのまま利用する。

- 距離の段階判定: `distanceBetween`
- 表示上の範囲: ローカル投影平面のメートル距離
- 緯度による補正: 削除

これにより、オーストラリアや高緯度地域でも、近づくほど格子の1マスが小さくなる意味が変わらない。

### 7.4 タップと仮ポイント

画面タップは `screenToWorld` でローカル投影座標へ戻し、`unprojectWorld` で緯度経度へ変換して仮ポイントを作る。

- 空白タップの仮ポイント
- 点の選択
- 線の選択
- 観察記録の選択
- グリッド上での中心操作

全て同じ逆変換を使用する。表示だけローカルにしてタップだけWeb Mercatorに残す実装は禁止する。

### 7.5 中心計算と全体表示

複数地点の中心は、投影平面上の単純な `x/y` 平均ではなく、緯度経度から決める。

候補は次の順で検証する。

1. 球面上の単位ベクトル平均による地理的中心
2. 日付変更線をまたぐ最短経度差を使った局所中心
3. 地点数が少なく範囲が限定される場合のローカル投影平面平均

`🔲` の全体表示は、中心を決めてから全地点を再投影し、投影後の範囲でスケールを決める。

## 8. データと保存形式

### 8.1 保存するもの

- `geo.lat`
- `geo.lng`
- `geo.accuracy`
- 地点名、コメント、写真など既存の属性
- 観察記録の各軌道点の緯度経度

### 8.2 保存しないもの

- 現在の投影平面上の `x/y` を正本として扱わない
- 一時的な投影中心を地点データへ焼き付けない
- `world` / `local` の一時表示状態を共有データの意味にしない

ワークスペースのメタ情報に現在の投影方式を記録する場合は、表示設定として扱う。

```json
{
  "projection": {
    "mode": "local",
    "version": 1
  }
}
```

既存の保存データは、読み込み時に緯度経度から表示座標を再構築する。開発段階のため、旧Web Mercatorの `x/y` を必須とする下位互換は持たない。

## 9. 実装フェーズ

### Phase 0: 基準値とテストの固定

- 現在の主要操作を確認する。
- 東京、シドニー、レイキャビク、アラスカ、南極に近い地点、日付変更線の両側をテストケースにする。
- 球面距離と、表示上の中心からの距離が大きく乖離しない基準を決める。
- 既存の追跡・観察・保存・読み込みが壊れていない状態をベースラインとして記録する。

### Phase 1: 日付変更線の補正

ローカル投影へ全面移行する前に、現在のWeb Mercatorでも日付変更線付近を扱えるようにする。

- 最短経度差の共通化
- 線分描画のラップ処理
- 全体表示の経度範囲計算
- 点・線のヒットテスト
- 起点・対象の自動線

このフェーズは独立した不具合修正として検証し、ローカル投影実装後も境界ケースの回帰テストとして残す。

### Phase 2: 投影コンテキストの導入

- `state.projection` を追加
- `projectGeo` / `unprojectWorld` の入口を作る
- 描画・操作処理からWeb Mercator関数への直接依存を外す
- 既存の表示を保ったまま、投影を差し替えられる構造にする

この時点で、まだ投影結果をWeb Mercatorにしてもよい。目的は責務分離である。

### Phase 3: ローカル投影の導入

- 方位距離投影の正投影・逆投影を実装
- 表示中心の決定と更新タイミングを実装
- グリッドをメートル間隔で描画
- 点、線、現在地、仮ポイント、観察軌道を切り替える
- パン、ズーム、ピンチ、空白タップを検証

まずは手動の中心操作と通常表示で完成させ、追跡モードは次フェーズに分ける。

### Phase 4: 追跡・観察との統合

- 追跡開始時の投影中心を固定
- 現在地移動時のビューポート追従
- 対象距離による段階スケール
- 起点から対象への基準線
- 実軌道の記録・再描画・保存・読み込み
- 追跡完了後に投影と軌道が不自然に変わらないことを確認

### Phase 5: 世界俯瞰と自動モード判定

- `🔲` の全体表示でローカル投影と世界俯瞰を使い分ける
- 日付変更線をまたぐ地点群を最短範囲で配置
- 高緯度で地点群が広い場合の警告またはモード表示を検討
- 画面上に投影の技術用語を出さず、必要なら設定画面に表示モードを置く

初回リリースでは、明示的な「投影方式切り替え」を増やさず、自動判定を優先する。

## 10. 検証項目

### 10.1 距離と配置

- 同じ緯度で東西に10km離れた地点が、東京・シドニー・高緯度地域で同程度の格子距離になる。
- 極に近い地点でも、地点が画面端へ不自然に引き伸ばされない。
- 日付変更線の東西にある近接地点が、画面上でも近くに表示される。
- 起点と対象の線が、長い経度方向を回り込まない。
- 実距離表示と格子上の距離の意味が一致する。

### 10.2 操作

- パン後も地点、線、軌道が互いにずれない。
- ズーム、ピンチで中心位置が飛ばない。
- 空白タップした仮ポイントの緯度経度が正しい。
- 点、線、読み込み観察記録を正しくタップ選択できる。
- 現在地センタリングと追跡の挙動が従来の操作体系を保つ。

### 10.3 保存・読み込み

- ローカル投影中に保存しても、保存ファイルに表示座標の歪みが残らない。
- 読み込み後、現在地や表示中心が変わっても地点が正しい場所に出る。
- 観察軌道を保存・複数読み込みしても、全ての軌道点が同じ場所に戻る。
- 地点リスト共有ファイルが、地域や経度境界に関係なく再現される。

### 10.4 パフォーマンス

- 通常の数十〜数百地点で、現在地更新ごとの再投影が操作を阻害しない。
- 観察軌道2,000点上限でも、追跡中の描画が滑らかである。
- 既存のCanvas描画回数を必要以上に増やさない。

## 11. 受け入れ条件

以下を満たした時点で、ローカル投影対応を完了とする。

- 地点データの緯度経度が正本として維持されている。
- 東京、シドニー、高緯度地域、日付変更線付近で、近い地点が画面上でも近くに表示される。
- 格子間隔が「表示中心付近の実距離」として一貫する。
- 点線、通常線、観察軌道、起点・対象・現在地の描画位置が同じ投影で一致する。
- パン、ズーム、ピンチ、タップ、仮ポイント登録が破綻しない。
- 追跡中の段階スケールと観察記録の保存・読み込みが維持される。
- `🔲` の全体表示で、日付変更線や高緯度の地点群が極端に分断されない。
- 既存のローカル保存・地点リスト・観察記録を再読み込みしても座標が変わらない。

## 12. リスクと判断

### 12.1 すべてを単一投影で解決しようとしない

地球全体を一つの平面に置き、同時に全地点の距離・方向・形状を正確に保つことはできない。したがって、ローカル観察と世界俯瞰を用途として分けるのが妥当である。

### 12.2 投影中心の自動移動に注意する

中心を毎回現在地へ移すだけでは、過去の実軌道が動いたように見える。追跡中は投影中心を固定し、画面の追従だけを動かす設計を基本とする。

### 12.3 極点の完全対応は別問題

北極点・南極点そのものでは経度が定義できない。極付近の表示はローカル投影で改善できるが、極点を通常の地点と完全に同じ操作感で扱うには、極を中心とした専用の方位基準や表示ルールが必要になる。Phase 5以降の検討事項とする。

### 12.4 まず直す範囲

実装順は、次の順が最も安全である。

1. 日付変更線の最短経路補正
2. 投影コンテキストの分離
3. ローカル投影を通常のグリッドへ導入
4. 追跡・観察との統合
5. 世界俯瞰の自動切り替え

この順であれば、各段階で実機確認でき、世界展開向けの大きな変更を一度に入れずに済む。
